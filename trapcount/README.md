# TrapCount — подсчёт животных на видео с фотоловушек

TrapCount оценивает число различимых животных, появившихся за один клип, и показывает треки, по которым получилась оценка. Если два животных проходят по очереди, максимум по одному кадру даст единицу. Подсчёт по трекам может учесть обоих, но при перекрытии или редкой выборке одно животное иногда получает несколько ID. Проект измеряет ошибки обоих подходов и стоимость обработки при 6, 3 и 1 кадре в секунду.

## Быстрый запуск

Выполните команды из папки `trapcount/` с [uv](https://docs.astral.sh/uv/) и Python 3.12. Синтетические клипы генерируются локально, без скачивания датасета и весов модели.

```bash
uv run --python 3.12 trapcount fixture --sites 5
uv run trapcount benchmark --root data/fixture --detector fixture --fps 6 3 1 --out runs/fixture
uv run trapcount infer --input data/fixture/frames/test/site-05-sequential --detector fixture --out runs/demo
uv run python -m unittest discover -s tests -v
```

Откройте `runs/demo/index.html`, чтобы увидеть треки двух последовательно появляющихся объектов, или `runs/fixture/index.html`, чтобы сравнить методы и разобрать ошибки. `runs/demo/tracks.json` содержит таймкоды, ID, координаты рамок и оценки детектора.

## Как устроен эксперимент

| Метод | Как считает |
| --- | --- |
| `max-frame` | Берёт максимум детекций среди выбранных кадров. |
| `geometry` | Сопоставляет детекции с активными треками венгерским алгоритмом по IoU предсказанных рамок и нормированному смещению центра. |
| `appearance` | Добавляет к геометрической стоимости расстояние между RGB-гистограммами центральных областей рамок. |

- **Единый эталон.** При каждой частоте сравниваем число оценённых животных с числом аннотированных ID во всём клипе на 6 FPS. Пропуски, возникшие уже на этапе выборки кадров, считаем отдельно.
- **Оценка с эталонными рамками.** Повторяем эксперимент с рамками из разметки. Это помогает разделить ошибки детектора и ассоциации. MAE, смещение, доли недосчёта и пересчёта оценивают итоговый подсчёт. IDF1, фрагментации и объединения треков показывают ошибки идентификации даже при верном итоговом числе.
- **Разбиение по локациям.** Train и test в SA-FARI не пересекаются по местам установки камер. Разницу MAE между трекером и `max-frame` считаем попарно на тех же клипах, а для 95%-го bootstrap-интервала пересэмплируем целые локации при наличии хотя бы пяти.
- **Скорость и разбор ошибок.** Отчёт сопоставляет MAE со средним и p95 времени декодирования выбранных JPEG, детекции, извлечения признаков и ассоциации. Срезы выделяют группы, краткие появления, перекрытия и кадры с низкой цветностью. Измерение исключает скачивание и построение отчёта.

## Что проверено

На 30 сгенерированных клипах с известной разметкой из пяти синтетических локаций получена следующая MAE в животных на клип.

| Частота | `max-frame` | `geometry` | `appearance` |
| --- | ---: | ---: | ---: |
| 6 FPS | 0,333 | 0,167 | 0,167 |
| 3 FPS | 0,333 | 0,167 | 0,167 |
| 1 FPS | 0,500 | 3,667 | 0,500 |

На 1 FPS геометрический трекер в этом наборе сильнее дробит траектории, а цветовой признак уменьшает число таких разрывов. Эти числа характеризуют синтетические сценарии. На реальном клипе SA-FARI проверены трекинг и отрисовка по ручным рамкам на 12 кадрах. Количественная оценка на тестовом сплите SA-FARI и инференс с весами MegaDetector остаются непроверенными.

## Запуск на реальных данных

**Свой клип.** По умолчанию используется MegaDetector v5a с порогом уверенности 0,30. Веса загружаются при первом запуске. Можно передать папку с пронумерованными JPEG или PNG и указать исходную частоту через `--source-fps`.

```bash
uv run --python 3.12 --extra real trapcount infer --input clip.mp4 --fps 3 --out runs/clip
```

**SA-FARI.** [Датасет фотоловушек](https://huggingface.co/datasets/facebook/SA-FARI) содержит треки отдельных животных. Примите условия доступа к разметке на Hugging Face перед входом. Команды скачивают воспроизводимые подвыборки по локациям, проверяют декодирование выбранных кадров и запускают оценку.

```bash
uv run --python 3.12 --extra real hf auth login
uv run --extra real trapcount fetch --split train --limit 60 --seed 42
uv run --extra real trapcount fetch --split test --limit 150 --seed 42
uv run --extra real trapcount audit --split test --limit 150 --seed 42 --decode
uv run --extra real trapcount benchmark --split test --limit 150 --seed 42 --fps 6 3 1 --out runs/sa-fari
```

Настройки можно подбирать на `train` и фиксировать перед оценкой на `test`. Для полного тестового сплита уберите `--limit` одновременно из `fetch`, `audit` и `benchmark`. Для фиксации версии разметки укажите `fetch --revision <commit>`. Бэкенд `--detector cached --predictions FILE --prediction-root DIR` принимает стандартный [формат MegaDetector](https://megadetector.readthedocs.io/en/latest/userguide.html). Время работы такого бэкенда отражает поиск по готовым детекциям в памяти.

`index.html` содержит график точности и времени, таблицы и анимированные примеры. `per_clip.csv` и `manifest.csv` можно соединить по `clip`, чтобы проверить любой срез. `run.json` фиксирует настройки, версии зависимостей, ID клипов и SHA-256 разметки.

ID действуют в пределах клипа. Повторные появления между клипами учитываются отдельно. SA-FARI размечает различимые особи в роликах с животными. Для оценки численности популяции или доли ложных срабатываний на пустых клипах нужны другие данные.

## Структура

```text
trapcount/
├── README.md
├── pyproject.toml           # зависимости и CLI
├── src/trapcount/
│   ├── cli.py               # команды загрузки, оценки и инференса
│   ├── dataset.py, media.py # разметка, клипы и выборка кадров
│   ├── detectors.py        # MegaDetector, JSON и синтетический детектор
│   ├── core.py, tracking.py # геометрия и ассоциация детекций
│   ├── benchmark.py        # метрики, парные сравнения и срезы
│   ├── report.py           # HTML, анимации, CSV и JSON
│   └── fixture.py          # воспроизводимые синтетические клипы
└── tests/                  # тесты метрик, трекера, форматов и CLI
```
