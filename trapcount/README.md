# TrapCount — подсчёт животных на видео с фотоловушек

TrapCount оценивает число различимых животных, появившихся за один клип, и показывает треки, по которым получилась оценка. Если два животных проходят по очереди, максимум по одному кадру даст единицу. Подсчёт по трекам может учесть обоих, но при перекрытии или редкой выборке одно животное иногда получает несколько ID. Проект измеряет ошибки обоих подходов и стоимость обработки при 6, 3 и 1 кадре в секунду.

## Результаты на SA-FARI

Первый прогон охватил **30 из 833 клипов** официального тестового сплита. Выборка с `seed=42` включает 30 локаций и 2 720 размеченных кадров. В 25 клипах размечено по одному животному, в пяти — по два. Использовались опубликованные веса MegaDetector V6 YOLOv10 Compact (ONNX, 640 × 640, CPU), порог 0,30 и настройки трекеров по умолчанию.

| Частота | MAE `max-frame` | MAE `geometry` | MAE `appearance` |
| --- | ---: | ---: | ---: |
| 6 FPS | 0,600 | 2,333 | 2,200 |
| 3 FPS | 0,500 | 1,933 | 1,800 |
| 1 FPS | **0,300** | 1,467 | 1,467 |

`max-frame` при 1 FPS совпал с эталонным числом в 22 из 30 клипов. Все размеченные ID сохранились в выборке кадров при 1 FPS. У `appearance` при этой же частоте MAE была выше на 1,167 животных на клип (парный 95%-й bootstrap-интервал по локациям от 0,767 до 1,633). На эталонных рамках MAE этого трекера снизилась до 0,367, а среднее смещение осталось положительным. Такой результат показывает вклад детекций в ошибку и сохраняющееся завышение при ассоциации. Пять клипов с несколькими животными дают ограниченные основания судить о последовательных появлениях.

## Быстрый запуск

Выполните команды из папки `trapcount/` с [uv](https://docs.astral.sh/uv/) и Python 3.12. Синтетические клипы генерируются локально, без скачивания датасета и весов модели.

```bash
uv run --python 3.12 trapcount fixture --sites 5
uv run trapcount benchmark --root data/fixture --detector fixture --fps 6 3 1 --out runs/fixture
uv run trapcount infer --input data/fixture/frames/test/site-05-sequential --detector fixture --out runs/demo
uv run python -m unittest discover -s tests -v
```

Откройте `runs/demo/index.html`, чтобы увидеть треки двух последовательно появляющихся объектов, или `runs/fixture/index.html`, чтобы сравнить методы и разобрать ошибки. `runs/demo/tracks.json` содержит таймкоды, ID, координаты рамок и оценки детектора.

## Как устроен эксперимент

| Метод | Как считает |
| --- | --- |
| `max-frame` | Берёт максимум детекций среди выбранных кадров. |
| `geometry` | Сопоставляет детекции с активными треками венгерским алгоритмом по IoU предсказанных рамок и нормированному смещению центра. |
| `appearance` | Добавляет к геометрической стоимости расстояние между RGB-гистограммами центральных областей рамок. |

- **Единый эталон.** При каждой частоте сравниваем число оценённых животных с числом аннотированных ID во всём клипе на 6 FPS. Пропуски, возникшие уже на этапе выборки кадров, считаем отдельно.
- **Оценка с эталонными рамками.** Повторяем эксперимент с рамками из разметки. Это помогает разделить ошибки детектора и ассоциации. MAE, смещение, доли недосчёта и пересчёта оценивают итоговый подсчёт. IDF1, фрагментации и объединения треков показывают ошибки идентификации даже при верном итоговом числе.
- **Разбиение по локациям.** Авторы SA-FARI формировали train и test по местам установки камер. Разницу MAE между трекером и `max-frame` считаем попарно на тех же клипах. Для 95%-го bootstrap-интервала пересэмплируем целые локации. Клипы с неизвестной локацией входят в общие метрики и образуют одну группу для bootstrap.
- **Скорость и разбор ошибок.** Отчёт сопоставляет MAE со средним и p95 времени декодирования выбранных JPEG, детекции, извлечения признаков и ассоциации. Срезы выделяют группы, краткие появления, перекрытия и кадры с низкой цветностью. Измерение исключает скачивание и построение отчёта.

## Синтетический контроль

На 30 сгенерированных клипах с известной разметкой из пяти синтетических локаций получена следующая MAE в животных на клип.

| Частота | `max-frame` | `geometry` | `appearance` |
| --- | ---: | ---: | ---: |
| 6 FPS | 0,333 | 0,167 | 0,167 |
| 3 FPS | 0,333 | 0,167 | 0,167 |
| 1 FPS | 0,500 | 3,667 | 0,500 |

На 1 FPS геометрический трекер в этом наборе сильнее дробит траектории, а цветовой признак уменьшает число таких разрывов. Эти числа характеризуют синтетические сценарии.

## Запуск на реальных данных

**Свой клип.** По умолчанию используется MegaDetector v5a с порогом уверенности 0,30. Веса загружаются при первом запуске. Можно передать папку с пронумерованными JPEG или PNG и указать исходную частоту через `--source-fps`.

```bash
uv run --python 3.12 --extra real trapcount infer --input clip.mp4 --fps 3 --out runs/clip
```

**SA-FARI.** Примите условия доступа к разметке на странице [датасета](https://huggingface.co/datasets/facebook/SA-FARI). Скачайте [архив официальных кадров](https://storage.googleapis.com/cxl-public-camera-trap/sa_fari/sa_fari_test_tars/JPEGImages_6fps/sa_fari_test_00.tar.gz) (3,65 ГБ) и сохраните его как `data/sa-fari/sa_fari_test_00.tar.gz`. Из [архива модели Microsoft](https://zenodo.org/records/21196048/files/camera_trap__detector__MDV6-yolov10-c.zip?download=1) извлеките `MDV6-yolov10-c/1/model.onnx` в `weights/MDV6-yolov10-c.onnx`. SHA-256 модели — `d38a71b93dcf34147261c6af7665cf3ad2495c924d15503fd88304950cf8eb6a`.

```bash
uv run --python 3.12 --extra data hf auth login
uv run --extra data trapcount fetch --split test --revision b38cec702475f707faa759ac49d5b2082467c6e1 --frame-archive data/sa-fari/sa_fari_test_00.tar.gz
uv run --extra data trapcount audit --split test --decode
uv run --extra data --extra onnx trapcount benchmark --split test --seed 42 --fps 6 3 1 --detector onnx --model weights/MDV6-yolov10-c.onnx --threshold 0.30 --jobs 8 --examples 0 --out runs/sa-fari
```

Для прогона на 30 клипах добавьте `--limit 30 --seed 42` к `fetch`, `audit` и `benchmark`. Без `--frame-archive` команда `fetch` скачивает отдельные JPEG. Для последовательного замера времени обработки используйте `--jobs 1`. При параллельном запуске измеренное время включает конкуренцию за ресурсы. Бэкенд `--detector cached --predictions FILE --prediction-root DIR` принимает стандартный [формат MegaDetector](https://megadetector.readthedocs.io/en/latest/userguide.html). Время работы такого бэкенда отражает поиск по готовым детекциям в памяти.

`index.html` содержит график точности и времени и таблицы. Для анимированных примеров задайте `--examples 6`. `per_clip.csv` и `manifest.csv` можно соединить по `clip`, чтобы проверить любой срез. `run.json` фиксирует настройки, версии зависимостей, ID клипов, SHA-256 разметки и ONNX-модели.

ID действуют в пределах клипа. Повторные появления между клипами учитываются отдельно. SA-FARI размечает различимые особи в роликах с животными. Для оценки численности популяции или доли ложных срабатываний на пустых клипах нужны другие данные.
